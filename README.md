# Yu: study

iPad에서 시험지 PDF, 풀이 회차, 오답 및 교재 목차를 관리하는 오프라인 개인 학습 서재입니다. GitHub에 등록하는 파일은 앱 소스, 아이콘과 가상 테스트 코드입니다.

## v0.2.0 · 아이패드에 직접 저장

아이패드에서 선택한 PDF와 학습 기록은 해당 기기의 IndexedDB에 저장됩니다. PC에 등록했던 자료는 PC 브라우저에 보관됩니다. 업데이트는 기존 데이터베이스 이름과 버전 1을 그대로 사용합니다.

홈 또는 자료실의 **PDF 가져오기**를 눌러 파일 앱에서 PDF를 선택하고, 과목과 문항 수를 확인한 뒤 **등록**을 누르세요. 파일 선택기가 화면에 유지되며 읽기·중복 검사·저장 진행 상황이 표시됩니다. 여러 파일은 한 개씩 처리합니다. 등록 후에는 자료실 필터가 초기화되어 새 PDF를 바로 확인할 수 있습니다.

파일을 읽지 못하면 파일 앱에서 PDF를 열어 다운로드를 완료하거나 **나의 iPad**에 복사한 뒤 다시 선택하세요. 오류는 가져오기 창에 표시됩니다. **다시 시도**, **건너뛰기**, **닫기**로 이어서 진행할 수 있습니다. 읽는 동안 **읽기 취소**를 사용할 수 있습니다. 이미 등록한 PDF가 휴지통에 있으면 자료실의 휴지통에서 복구하세요.

업데이트를 받으려면 인터넷에 연결된 상태에서 앱을 연 뒤 앱 창을 모두 닫고 다시 여세요. 설정에 **기기 저장 · v0.2.0**이 표시되면 새 버전입니다. Safari 데이터 삭제는 기존 학습 기록을 지울 수 있으므로 업데이트에는 사용하지 마세요.

검증은 Chromium 및 WebKit 브라우저에서 진행합니다. `scripts/import-test.mjs`는 터치 기반 파일 선택, 기존 버전 자료 보존, MIME 정보가 없는 PDF, 여러 파일 등록, 중복 파일, 읽기 오류, 저장 공간 부족 시 롤백과 재시도를 검사합니다. `scripts/browser-test.mjs`는 PDF 열람·추출, 백업·복원 및 오프라인 업데이트를 검사합니다. 실제 iPad의 파일 앱과 iCloud 다운로드 동작은 실기기 확인이 필요합니다.

## 설치 및 첫 사용

1. Pages 배포가 완료된 뒤 Safari에서 저장소의 Pages 주소를 열고 첫 설치 시 인터넷 연결을 유지하세요. 공유 메뉴에서 **홈 화면에 추가**를 선택하고 홈 화면 아이콘에서 자료를 등록하세요.
2. **PDF 가져오기**에서 파일을 선택하고 과목, 연도, 시험 종류와 문항 수를 확인합니다. 기본값은 20이며 25 또는 사용자 지정 번호를 입력할 수 있습니다. 원본은 SHA-256으로 중복 검사합니다.
3. 자료실에서 PDF를 열고 틀린 번호를 터치한 후 **선택 저장**을 누릅니다. 현재 회차는 다시 수정할 수 있습니다. 다시 풀 때 **새 회차**를 누르면 반복 오답으로 누적됩니다.
4. **문항 영역 검수**에서 문항 번호를 고르고 인식 영역을 확인합니다. 스캔본이거나 경계가 맞지 않으면 초기화한 뒤 **영역 그리기**로 페이지 위에 드래그합니다. 다른 페이지에서도 영역을 추가할 수 있습니다. 공통 지문도 해당 문제의 영역으로 추가합니다.
5. **설정 → 목차 JSON 가져오기**에서 개인 파일을 선택합니다. 정식 테마와 참조 항목, PART와 CHAPTER 및 교재 페이지를 보존합니다. 오답노트의 **분류 및 복습**에서 주 테마와 숙지 상태를 선택하세요.
6. 오답노트에서 테마나 반복 여부를 선택하면 현재 필터에 맞는 문항의 영역만 표시됩니다. **A4 PDF 출력**으로 PDF를 생성한 뒤 미리보기, 파일 저장 또는 공유를 선택합니다. 출력은 지정 영역의 래스터 이미지로 구성됩니다.
7. **분석 및 일괄 분류 → GPT 분류 요청**에서 내용을 확인한 뒤 직접 복사합니다. 응답을 **분류 결과 가져오기**에 붙여넣고 승인할 행을 선택합니다. 화면에서 실행 취소할 수 있습니다. 앱은 원문을 외부에 자동 전송하지 않습니다.

분류 결과 예시 (문항과 테마 ID는 로컬 데이터에 존재해야 합니다).

```json
{"version":1,"results":[{"questionId":"demo#3","primaryThemeId":"demo-theme","secondaryThemeIds":[],"confidence":0.8,"reason":"가상 분류 근거","needsReview":true}]}
```

## 백업과 업데이트

설정에서 **전체 백업 저장**을 눌러 ZIP을 iCloud Drive 등에 보관하세요. ZIP에는 원본 PDF, 개인 기록 및 목차가 들어갑니다. 복원 시 체크섬, ID, 파일 목록과 일부 참조를 검사하고 교체 여부를 묻습니다. 파일과 메타데이터를 한 IndexedDB 트랜잭션에서 교체합니다. 최근 백업 날짜는 다운로드를 요청한 시점입니다. 파일 앱에 저장됐는지 확인하세요.

같은 GitHub 계정, 저장소 이름, URL, 홈 화면 실행 방식을 유지하세요. 설치된 앱 창을 모두 닫았다가 다시 열면 준비된 업데이트를 적용합니다. 서비스 워커는 이 앱의 정적 파일 캐시만 교체합니다. IndexedDB 이름은 `yu-study-archive`, 버전은 1입니다. `files`는 SHA-256 기준 원본 Blob, `meta`는 문서·회차·문항·발생 이력·검수 영역·테마·복습 상태입니다. 향후 버전은 upgrade 트랜잭션에서 기존 자료를 이관해야 합니다. 사이트 데이터 삭제, 기기 손실, 브라우저 저장 공간 회수에 대비해 앱 외부 백업을 유지하세요.

## 개발과 배포

Node.js 22.12 이상에서 `npm install`, `npm test`, `npm run build`를 순서대로 실행합니다. `dist/`만 배포합니다. Vite가 없는 사전 설치 환경은 `YU_DEPENDENCIES`에 pdfjs-dist 및 jszip이 설치된 node_modules 절대 경로를 지정하고 `node scripts/build.mjs`로 동일 기능의 번들 없는 정적 패키지를 생성할 수 있습니다. HTTP 서버로 /yu-study/ 하위에 마운트합니다.

GitHub 저장소 Settings → Pages → Build and deployment → Source에서 **GitHub Actions**를 선택합니다. main에 push하거나 Actions의 **Test and publish Yu study**를 실행합니다. 테스트와 빌드가 성공해야 배포 단계가 실행됩니다. Vite base는 /yu-study/이고 manifest, worker, 아이콘 및 오프라인 캐시는 프로젝트 하위 경로를 기준으로 합니다. 외부 CDN이나 서버 DB는 사용하지 않습니다.

Windows 개발과 iPad 홈 화면 설치를 위해 PWA를 선택했습니다. 네이티브 앱은 OS 파일 관리와 직접 통합할 수 있지만 Apple 빌드·서명 환경을 요구합니다. 이 구현은 IndexedDB에 원본을 저장하며 백업 ZIP으로 브라우저 외부에 보존합니다.

## 현재 범위

문항 경계 감지는 텍스트 위치와 번호 순서에 기반한 추정입니다. 스캔, 복잡한 2단, 회전, 공통 지문은 수동 검수가 필요합니다. 마지막 문항이 다음 페이지까지 이어지면 수동으로 추가하세요. 다중 페이지를 연속 렌더링하는 뷰어, OCR, 답안·해설 자동 연결, 사진 및 CSV 목차 편집, 대용량 백업 스트리밍, 출력 옵션 전체와 iPad 실기기 성능 검증은 후속 범위입니다. 복원과 PDF 생성의 메모리 사용량은 파일 크기에 따라 증가합니다.
